# Somon Rent Bot — ТЗ + промпт для Claude Code

Личный телеграм-бот: следит за новыми объявлениями об аренде квартир в Душанбе на somon.tj и мгновенно присылает те, что подходят под твои фильтры.

---

# ЧАСТЬ 1. ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## 1.1 Цель

Получать уведомление в Telegram в течение 30–90 секунд после публикации нового объявления об аренде квартиры в Душанбе, подходящего под заданные условия. Цель — быть первым, кто позвонит арендодателю.

## 1.2 Источник данных

Только `somon.tj`.

| Что | Значение |
|---|---|
| Базовый раздел | `https://somon.tj/nedvizhimost/arenda-kvartir/dushanbe/` |
| 1-комнатные | `https://somon.tj/nedvizhimost/arenda-kvartir/1-komnatnyie/dushanbe/` |
| 2-комнатные | `.../2-komnatnyie/dushanbe/` |
| 3-комнатные | `.../3-komnatnyie/dushanbe/` |
| 4-комнатные | `.../4-komnatnyie/dushanbe/` |
| Посуточно (опционально) | `https://somon.tj/nedvizhimost/arenda-posutochno/` |
| Пагинация | `?page=2`, `?page=3` … |
| Ссылка объявления | `https://somon.tj/adv/{ID}_{slug}/` |

**Ключевые технические факты (проверены):**

1. Сайт построен на **Next.js**. Значит, прежде чем писать HTML-парсер, нужно проверить наличие структурированных данных:
   - блок `<script id="__NEXT_DATA__" type="application/json">` в HTML;
   - RSC-payload (`self.__next_f.push([...])`) в inline-скриптах;
   - внутренние JSON-эндпоинты (посмотреть в DevTools → Network → Fetch/XHR при переключении страницы/сортировки).
   Если найдётся JSON — использовать его как основной источник, а HTML-парсер оставить как fallback. Это на порядок надёжнее и переживёт редизайн.

2. **ID объявления — целое число, монотонно возрастает.** Из `/adv/17005957_.../` извлекается `17005957`. Это главный признак новизны: любое объявление с `id > last_seen_max_id` — новое. Не полагаться на текст даты («18 минут назад», «Сегодня», «Вчера») — он неточный и локализованный.

3. **VIP / ТОП блоки.** В начале выдачи идут платно продвинутые объявления, часто недельной и месячной давности. Их обязательно нужно определять и игнорировать (по бейджу `VIP`/`ТОП` в карточке). Реально новые объявления идут после этих блоков.

4. **Сортировка.** На странице есть переключатель «Новые / Подходящие / Сначала дешевле / Сначала дорогие». Нужно определить параметр URL для сортировки по новизне (через DevTools) и всегда использовать его. Если параметр найти не удалось — сортировать самостоятельно по ID после парсинга.

5. Иногда сайт отдаёт баннер-заглушку («Ваш аккаунт был заблокирован на somon.tj») — признак срабатывания анти-бот защиты. Обрабатывать отдельно (см. 1.7).

## 1.4 Фильтры

Хранятся в БД, редактируются командами бота **и** задаются дефолтами в `.env`.

**Числовые:**
- `price_min`, `price_max` (сомони/мес)
- `rooms` — список: `[1, 2, 3]`
- `area_min`, `area_max`
- `floor_min`, `floor_max`
- `exclude_first_floor` (bool), `exclude_last_floor` (bool, если этажность известна)

**Текстовые:**
- `districts_include` — список ключевых слов; если непустой, в `title` должно встретиться хотя бы одно (регистронезависимо, с учётом таджикской латиницы/кириллицы: `Шохмансур`/`Шоҳмансур`, `Сино`, `Фирдавси`/`Фирдавсӣ`, `Исмоили Сомони`, `Центр`, `46 мкр` и т.п.)
- `districts_exclude` — стоп-слова по району
- `keywords_exclude` — глобальные стоп-слова в заголовке, дефолт: `посуточно`, `суточно`, `на сутки`, `комната`, `койко`, `хостел`, `общежитие`
- `only_with_photo` (bool)
- `skip_promoted` (bool, дефолт `true`) — не слать VIP/ТОП
- `blocked_authors` — список `author_url`/`author_name` (агентства, которые надоели)

**Нормализация текста при сравнении:** привести к нижнему регистру, заменить таджикские диакритики на базовые буквы (`ӣ→и`, `ӯ→у`, `ҳ→х`, `қ→к`, `ҷ→ч`, `ғ→г`), убрать лишние пробелы. Иначе «Фирдавсӣ» не совпадёт с «Фирдавси».

**Логика:** объявление проходит, если удовлетворяет ВСЕМ активным фильтрам. Незаданный фильтр (`null`) не применяется. Если поле объявления не распарсилось (`null`) — фильтр по нему **не отсекает** объявление (лучше лишнее уведомление, чем пропущенная квартира).

## 1.5 Алгоритм работы

```
Старт
 ├─ загрузить конфиг и фильтры
 ├─ инициализировать SQLite
 ├─ ХОЛОДНЫЙ СТАРТ (если БД пустая):
 │    спарсить 1-ю страницу, записать все ID в seen БЕЗ отправки уведомлений,
 │    сохранить max_id. Иначе бот зальёт 50 сообщений при первом запуске.
 └─ запустить цикл опроса

Цикл (каждые POLL_INTERVAL секунд ± джиттер 0–15с):
 ├─ для каждого отслеживаемого URL:
 │    ├─ GET страница 1 (сортировка «новые»)
 │    ├─ распарсить карточки
 │    ├─ отбросить is_promoted (если skip_promoted)
 │    ├─ отобрать те, у которых id НЕ в таблице seen
 │    ├─ записать ВСЕ новые id в seen (даже отфильтрованные — чтобы не проверять повторно)
 │    ├─ применить фильтры
 │    └─ отсортировать прошедшие по id ↑ и отправить уведомления
 ├─ если новых на 1-й странице >= 80% карточек → подгрузить page=2 (был всплеск)
 └─ спать
```

**Порог тишины:** если 3 цикла подряд не найдено ни одного нового ID вообще (даже отфильтрованного) — вероятно, парсер сломался или сайт блокирует. Написать админу предупреждение (не чаще 1 раза в час).

## 1.6 Формат уведомления

Одно сообщение с фото (если есть) и подписью в HTML-разметке:

```
🏠 <b>2-комн. квартира, 9 этаж, 70 м²</b>

💰 <b>6 000 сомони/мес</b>
📍 Зарафшон, назди посольства Америка
🏢 9 этаж · 70 м² · 2 комнаты
👤 Avenue Wolf
🕐 Найдено: 27.08 14:32 (через ~40 сек после публикации)

🔗 https://somon.tj/adv/17005957_.../
```

Inline-кнопки:
- `🔗 Открыть объявление` (URL)
- `🚫 Заблокировать автора` (callback)
- `⏸ Пауза 1 час` (callback)

Отправка **мгновенная**, по одному объявлению = одно сообщение. Соблюдать лимит Telegram (~30 msg/sec, но для одного чата ~1 msg/sec) — очередь отправки с интервалом 1 сек и retry при `RetryAfter`.

## 1.7 Устойчивость и анти-бан

- Реалистичные заголовки: `User-Agent` десктопного Chrome, `Accept-Language: ru-RU,ru;q=0.9,tg;q=0.8`, `Accept`, `Referer: https://somon.tj/`.
- Постоянная HTTP-сессия с cookie jar (`httpx.AsyncClient`), keep-alive.
- Джиттер интервала опроса, минимальный интервал — не чаще 20 сек.
- Экспоненциальный backoff при ошибках: 1 → 2 → 4 → 8 → 16 мин, максимум 30 мин.
- Отдельная обработка `403`, `429`, Cloudflare-челленджа, баннера «аккаунт заблокирован»: увеличить интервал в 3 раза на 30 минут и уведомить админа.
- Таймаут запроса 15 сек, 3 попытки.
- Опциональная поддержка HTTP/SOCKS5-прокси через `PROXY_URL` в `.env`.
- Любое падение парсера **не должно ронять процесс** — логировать, сохранить дамп HTML в `debug/` (последние 5 файлов), продолжить цикл.

## 1.8 Команды бота

Доступ только для `ADMIN_CHAT_ID` — всем остальным отвечать «Это личный бот» и игнорировать.

| Команда | Действие |

## 1.12 Критерии приёмки

1. `python -m bot.main` стартует без ошибок при корректном `.env`.
2. Первый запуск не спамит — только сообщение «Бот запущен, отслеживаю N объявлений».
3. `/test` возвращает 3 реальные распарсенные карточки с корректными ценой, комнатами, площадью, этажом.
4. Новое объявление, попадающее под фильтры, приходит в течение `POLL_INTERVAL + 10` сек.
5. Дублей нет: перезапуск бота не приводит к повторной отправке.
6. VIP/ТОП объявления не приходят при `SKIP_PROMOTED=true`.
7. При 403/429 бот не падает, уходит в backoff и пишет админу.
8. `pytest` проходит: тесты парсера на сохранённых фикстурах, тесты фильтров, тесты нормализации.

## 1.13 Ограничения

- Запросы — не чаще 1 раза в 20 секунд к одному URL, только публичные страницы, без обхода авторизации и капчи. Нагрузка сопоставима с обычным человеком, обновляющим страницу.
- Бот личный, один пользователь (`ADMIN_CHAT_ID`).
- Телефон продавца на somon.tj скрыт за кликом — бот **не** пытается его вытащить, только даёт ссылку.

## Критично — не пропусти

1. **ID объявления из URL `/adv/{ID}_slug/` — главный ключ.** Новизна определяется по `id > max_seen_id`, а НЕ по тексту даты («18 минут назад» / «Сегодня»).
2. **Холодный старт.** При пустой БД: спарсить страницу, записать все ID как виденные, НЕ отправлять уведомления. Иначе первый запуск зальёт чат.
3. **VIP/ТОП блоки** висят в начале выдачи и содержат старые объявления. Помечай `is_promoted=True` и по умолчанию не уведомляй о них.
4. **Записывай в `seen` ВСЕ новые ID**, включая те, что не прошли фильтры. Иначе бот будет их переобрабатывать каждый цикл.
5. **Нормализация таджикских диакритик** при сравнении текста: `ӣ→и, ӯ→у, ҳ→х, қ→к, ҷ→ч, ғ→г`. «Фирдавсӣ» и «Фирдавси» должны совпадать.
6. **Цена** приходит как `6 000 c.` с неразрывными пробелами; иногда два числа подряд (`5 700 c.7 500 c.`) — это новая и старая цена, брать **меньшую**.
7. **Если поле не распарсилось (`None`) — фильтр по нему не отсекает объявление.** Лучше лишнее уведомление, чем пропущенная квартира. Это осознанное решение, не «исправляй» его.
8. **Никаких падений процесса.** Любая ошибка парсинга/сети — залогировать, дампнуть HTML в `debug/`, продолжить цикл. Backoff при 403/429.
9. Парсер вынеси так, чтобы при редизайне сайта правился ОДИН файл `scraper/parser.py`.

## Стиль кода

- Python 3.11+, полные type hints, async везде, где есть I/O.
- Никаких «магических» значений в коде — всё в `config.py`.
- Комментарии и сообщения бота — на русском. Имена переменных и функций — на английском.
- Каждый модуль ≤ 300 строк, функции — маленькие и тестируемые.
- Не изобретай абстракции «на будущее». Делай ровно то, что в ТЗ.

## Чего НЕ делать

- Не пытайся обходить капчу, авторизацию или получать скрытый номер телефона.
- Не ставь интервал опроса меньше 20 секунд.
- Не используй Selenium/Playwright, если задача решается через httpx — они тяжёлые и ломают деплой на дешёвом VPS.
- Не добавляй веб-панель, БД на постгресе, поддержку нескольких пользователей и прочее, чего нет в ТЗ.

Когда закончишь, покажи: дерево проекта, содержимое `README.md`, вывод `pytest` и точную команду для запуска на сервере.
